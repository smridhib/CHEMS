# Contributing

## Branches

- `main` should remain stable.
- Use `feature/<short-name>` for features.
- Use `fix/<short-name>` for fixes.
- Use `docs/<short-name>` for documentation.

## Pull requests

Every pull request should include:

- What changed
- Why it changed
- How it was tested
- Screenshots for visual changes
- Any privacy or emergency-routing implications

At least one other contributor should review changes before merging.

## Definition of done

- Acceptance criteria are satisfied.
- Automated tests pass.
- Accessibility has been considered.
- No real student data, credentials, phone numbers, or secrets are committed.
- Emergency guidance has not been changed without documented review.

## Commit examples

- `feat: add residence selection flow`
- `fix: prevent expired duty contact from displaying`
- `docs: clarify 911 fallback behavior`
